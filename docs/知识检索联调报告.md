## 2026-10-21：文档级索引历史记录

以下结果属于分块改动前的代码，不作为当前版本的真实模型验收成绩；保留当时的原始证据与边界说明。

执行日期：2026-10-21。本报告区分组件接入、完整调用链路和回答质量。

## 结论

**Chroma 与 MCP 的本地完整调用链路已验证成功。** 已实际生成政策向量、持久化、启动 MCP 子进程、发现并调用检索工具，并让 Qwen3-32B 通过 FastAPI 聊天入口使用检索结果回答。

**检索质量及回答准确性尚未达标为完整验收。** 默认嵌入在6条中文小样本中首位命中3条；模型政策回答仍出现无依据的附加推断。本机网站继续使用 `local + lexical` 默认配置，本次没有将业务网站改为 Chroma/MCP，也没有使用业务数据库做测试。

因此可以说明“实现并验证可选 Chroma 向量检索与 MCP stdio 政策工具集成”，不能说“生产级中文 RAG、高准确率检索、零幻觉已验收”。

## 环境与实际链路

- Windows、Python 3.12.14；Chroma 0.5.23、MCP SDK 1.9.4、ONNX Runtime 1.31.0、NumPy 2.5.4、PostHog 3.25.0。
- Chroma 使用默认 `all-MiniLM-L6-v2` ONNX 嵌入，真实生成384维向量；集合为 `citymate_policies_v1`。
- 使用本项目3份政策源文件：预约规则、社区与积分、优惠与订单。一份文件对应一个向量记录，当前没有细粒度分块。
- 使用已存在的本机模型缓存；没有重新下载嵌入模型，不能声称验证了无缓存机器上的首次下载。
- 业务数据库为新建的隔离 SQLite，Redis 为 FakeRedis；Chroma 数据保存在每次验证独立的目录。MCP 使用真实 Python 子进程和 stdio 协议，不是模拟返回值。
- 最终模型为配置的 `Qwen/Qwen3-32B`，调用实际模型接口；HTTP 通过 FastAPI TestClient 运行真实应用生命周期、登录与 `/chat` 路由，没有浏览器或 TCP 服务器压测。

```text
政策文本 → Chroma 默认嵌入 → 持久化集合
                               ↑
聊天接口 → Qwen3-32B 工具调用 → MCP 客户端 → stdio 政策服务 → 向量查询
                               ↓
                  政策文本与来源 → 模型回答 → 聊天接口响应
```

## 检索质量与人工复核

| 问题 | 期望文档 | 实际首位 | 命中 |
|---|---|---|---|
| 预约草稿多久失效？ | 预约规则 | 社区与积分 | 否 |
| 填好了预订但还没提交，可以保留多久？ | 预约规则 | 社区与积分 | 否 |
| 签到能得多少积分？ | 社区与积分 | 社区与积分 | 是 |
| 我今天已经打过卡，再打卡还能加分吗？ | 社区与积分 | 社区与积分 | 是 |
| 抢到券显示处理中，是已经成功了吗？ | 优惠与订单 | 优惠与订单 | 是 |
| 平台会真的扣钱退款吗？ | 优惠与订单 | 社区与积分 | 否 |

当前总共只有3份文档，聊天默认检索会返回全部3份。模型能看到目标政策，并不能证明首位排序正确，也不能用“目标文档在返回结果里”证明大规模检索召回率。

最终三次聊天的自动检查验证 HTTP 200、实际模型调用、成功调用 `knowledge_search`、返回目标来源和关键数字/否定词；**这些检查不是完整语义评分**。人工阅读最终原文后确认：

- 预约有效期回答包含15分钟、确认后待审核等政策事实。
- 社区规则回答正确提到10积分及重复签到不再加分，但错误解释连续签到展示，并自行声称“您今日尚未签到”；该轮只调用政策检索，没有查询用户签到状态，这一用户状态断言没有依据。
- 优惠规则回答说明不进行真实扣款退款，但又将优惠券流程描述为“模拟预约流程”，业务概念仍有混淆。

因此最终 `3/3` 是**链路检查通过**，不代表3份回答都无误。尚需改进适合中文的嵌入选择、分块及相关性阈值，并扩大检索样本和政策回答语义检查；不能仅通过提示词承诺杜绝所有推断。

## 联调发现并修复的问题

最初环境没有安装 `requirements-ai.txt`。安装时，Chroma 0.5.23 的宽松依赖选择了 PostHog 7.73.2，查询虽能完成，但持续出现 `capture() takes 1 positional argument but 3 were given` 遥测接口不兼容日志。

现已在可选依赖中固定 `posthog==3.25.0`，并在 Chroma 初始化时设置 `anonymized_telemetry=False`。修复后重新运行完整后端回归和真实模型链路，未再出现该兼容性错误。没有修改模型密钥，也没有给 MCP 政策子进程传递模型密钥。
