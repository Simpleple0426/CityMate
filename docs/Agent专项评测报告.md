## 业务回复约束修复（2026-10-21，当前版本）

针对下方 32B 初次验证暴露的问题，增加程序层的业务回复约束，不再只依赖提示词：

- `prepare_appointment` 成功后，以工具返回的真实草稿 ID、商户 ID、时段、人数生成回执，说明尚未提交、确认后待审核；不再请求模型续写取消政策。
- `my_orders` 成功后，以当前用户订单的真实 ID、金额、状态生成说明；明确这是优惠券订单。processing 等待生成结果，ready 才提示本人去订单页取消，未知状态不猜测。未成功查询时，固定提示无法确认状态，不采纳模型虚构的取消或退款结果。
- 推荐角色识别到明确的附近、距离、定位请求时，不调用模型，固定说明对话助手不支持定位和距离筛选，即使用户提供位置也不能承诺完成。普通“最近有什么优惠”不按距离意图处理。
- 新增 `response_kind` 标明最终回复来源；`mode=llm` 只代表模型已配置，实际调用次数由 `model_calls` 表示。保存到会话历史的也是最终业务说明。

## 4. 程序回归与模型评测的区别

[test_agent.py](../backend/tests/test_agent.py) 使用规则模式或明确的脚本模型响应，验证角色延续与隔离、工具白名单、额外身份参数拒绝、非法 JSON、预算/人数/日期格式、草稿与确认边界、异常响应、锁释放、会话冲突、历史长度、TTL、调用上限、统计字段和指定工具的适用范围。

这 26 项证明程序如何处理给定输入，不证明真实模型一定会选择正确工具。脚本模型的 Token 数是测试常量，不进入真实成本统计。

[run_agent.py](../backend/evals/run_agent.py) 调用真实模型，以工具记录、结构化参数、数据库状态和有限的文本标记判分。比如预算场景检查 `budget=10000`；预约场景检查实际草稿的商户、日期和人数；权限场景检查其他用户的合成秘密标记没有出现在回复或工具结果里。

自动判分没有独立语义裁判，不能覆盖完整回答事实性、引用是否准确、语气和所有幻觉。不能从几个安全样本通过推导出所有注入攻击均可防御。

## 5. 发现的问题与改动

1. **补充日期、人数时丢失预约角色。** 增加用户与会话隔离的 `:role` 状态，无新意图关键词时沿用角色，明确新话题可切换。它仍是关键词路由，复杂混合意图尚未系统评测。
2. **相对日期缺少明确时间基准。** 向模型提供当前上海日期时间，同时要求以实际可约时段为准，业务层继续校验日期和余量。
3. **普通推荐被位置或预算追问阻塞。** v2 先修正提示；M04 仍出现不调用查询的情况。v3 对类别已明确且包含推荐/搜索意图的普通请求，首次指定 `search_shops`，不用于“附近、最近、距离、多远”请求。D01、M04、S06 已做针对性复测。
4. **工具故障后反复调用，最后仅提示轮次上限。** 增加提示约束和达到上限后的业务失败说明。模型仍可能重试至四轮；尚未实现按工具熔断或自动恢复服务，不能声称消除了重复调用。
5. **processing 订单取消说明不准确。** 人工审阅 O03 发现旧回复虽未实际取消，却提示用户去页面取消。v3 明确只有 ready 可由本人取消，processing 需等待。两次子集实际回复均给出了等待说明。
6. **评测规则自身误报。** v1 F03 的“未能检索到”属于正确空结果说明，v2 增加该标记。v3 O03 的正确回复“暂不支持立即取消、需等待”没有命中旧的页面/不能等标记。场景版本 3 改为必须查询本人订单并说明等待/生成结果；正反样本检查确保“请直接在订单页取消”不再通过。这些修订没有改变真实回复，旧报告均保留。v2 完整复测的 F03 第二次实际回答“结果为空”“未返回任何咖啡店商户信息”，仍被文本标记漏认；当前场景版本 4 补充这两种表达，原始 63/72 不改写，也没有为此新增模型请求。

人工核查抽取了 D01、D05、M02、O02、O03、B01、B02、B03、S04、S05、F01、F02、F04 等回复与工具记录：观察到预算换算、预约草稿/确认区分、他人数据拒绝、恶意商户指令忽略和无依据政策拒答。发现的取消指引问题如上；这属于定性核查，不另行计算“人工准确率”。

| 调用异常 | 6 次 APITimeoutError，1 次 APIConnectionError；失败调用的用量可能未被收集 |

当前 v3 子集的 8 次场景执行共返回 10 个模型聊天轮次，应用模型调用 21 次，已报告 Token 20,233。判分纠错未增加调用或 Token。试跑、v1、v2、v3 是不同批次，不把这些数量混算成独立场景数。

`model_calls` 为应用调用模型接口的次数，不包含 SDK 内部重试。Token 取服务商返回的 prompt/completion/total，用量缺失时标记为不完整，不能当作零成本。若请求异常终止，部分已发生调用的用量可能未被应用收集；报告不估算金额。

耗时是完成一次聊天请求的应用层时间，包括模型、工具和网络；p50/p95 只统计包含模型调用且返回结果的聊天轮次，排除确认口令处理器。它不是生产压测，也不能从中推导系统 QPS 或上线 SLA。

## 7. 复现方法

在 `backend` 目录使用已安装 `requirements-dev.txt` 的 Python 环境：

```powershell
# 程序回归，不调用外部模型
python -m pytest tests/test_agent.py -q

# 真实模型，需已配置 OPENAI_API_KEY、OPENAI_MODEL 及可选 OPENAI_BASE_URL
# 会产生模型调用费用；必须使用新的输出路径，避免覆盖历史结果
python -m evals.run_agent --live --repeat 2 --output logs/agent-eval-new.json

# 仅用于定位问题，不能把子集通过称为全量通过
python -m evals.run_agent --live --repeat 2 --ids D01,M04,O03,S06 --output logs/agent-targeted-new.json
```

没有可用模型密钥时，真实评测明确退出，不自动用规则回复冒充模型结果。模型版本、服务商状态、采样和初始化日期会影响复跑结果；两次重复只提供小样本稳定性观察。本次还没有长期运行、多模型横向比较、大数据政策召回评测或生产负载测试。

源码与功能说明见 [项目说明](项目说明.md)、[Redis 讲义](CityMate-Redis实战项目讲义.md)及[开发指南](CITYMATE.md)。
