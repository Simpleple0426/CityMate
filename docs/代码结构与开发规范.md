# CityMate 代码结构与开发规范

源码核对日期：2026-10-20。

当前仓库统一为 CityMate。业务后端、AI 助手和前端共用一套项目入口，旧 CoursePilot 教育版页面、API、评测和部署文件已移出活动源码。仓库目录暂时仍叫 `CoursePilot-GitHub`，不影响应用名称和启动方式。

文档约定：功能描述应能定位到具体代码；“有代码”“默认启用”“已验证”分别说明。未实现能力只放在边界说明；Chroma/MCP 的验证范围以 [知识检索联调报告](知识检索联调报告.md) 为准，不能把集成通过当成检索质量达标。测试数量附执行日期及环境，手工复现步骤不得冒充已完成记录。

```text

    app.py                 创建应用、生命周期、中间件、注册路由

      system.py            健康检查、指标、管理员统计
    service.py             核心服务：登录、商户、缓存、GEO

  tests/                   当前项目回归测试
```

`routers/commerce.py` 只处理 HTTP 参数和调用；`citymate/commerce.py` 实现数据库事务、库存和业务状态。两者职责不同。`app.py` 不再堆放全部请求模型和业务路由。

## 二、后端约定

1. 使用 Python 3.12，函数和文件采用 `snake_case`，类采用 `PascalCase`。
2. 请求模型放在 `schemas.py`，业务身份从 `current_user` 注入；管理员接口用 `require_admin`。
3. 路由通过 `get_platform` 取得当前应用服务，禁止用模块级变量保存用户或绑定某个测试实例。
4. 路由负责输入输出，业务规则和事务放在服务层，避免在路由中复制库存、订单或身份规则。
5. 新增表或字段使用 Alembic 迁移，不在普通请求中修改表结构。
6. 对金额使用整数分；时间和状态的约定沿用现有模型。订单 ID 按字符串传输。
7. Redis Key 统一经 `platform.key()` 生成；Lua、库存、锁与消息重试逻辑需保留对应测试。
8. 同步 IO 不直接阻塞异步聊天流程；可选 MCP/Chroma 依赖保留延迟导入。
9. Agent 评测区分脚本模型回归与真实模型效果。评测数据用独立 SQLite/FakeRedis，报告不得写入模型 Key、服务商错误原文或业务用户信息；失败样本和旧报告应保留，修改断言需说明原因。
10. 预约草稿回执、优惠券订单状态及明确不支持的定位能力由 `assistant.py` 的业务模板和能力分支输出。不要把模板再交给模型润色；新状态须同步业务校验、模板和测试。`mode` 不是本轮模型调用证明，应结合 `model_calls`、`response_kind` 查看。

Black 配置在 `backend/pyproject.toml`，统一 100 字符行宽。开发依赖固定在 `requirements-dev.txt`，其包含基础运行依赖；可选检索依赖独立放在 `requirements-ai.txt`，这是依赖分组，不是两套项目。

## 三、前端约定

使用 Vue 3 组合式 API、JavaScript ESM 和统一的 `lib/http.js` 客户端。服务端 Session 由 HttpOnly Cookie 标识，组件不保存登录 Token。

所有请求通过 `/api` 同源代理，上传通过 `/uploads`；不再保留旧版 Python/Java 后端切换。HTTP 客户端统一负责 CSRF 请求头、Cookie、JSON、上传和 401 错误行为。

Prettier 配置在 `frontend/.prettierrc.json`，使用两空格、单引号、无分号及 100 字符行宽。根目录 `.editorconfig` 统一编码、缩进和换行。

`App.vue` 仍承载当前页面组合和业务交互。后续新增独立页面时再按业务提取组件，避免仅为目录形式增加没有职责的空文件。

助手回复通过 `MarkdownMessage.vue` 和 `lib/markdown.js` 渲染；用户输入保持文本插值。禁止把模型原文直接传给 `v-html`，保持 `html: false`、默认危险 URL 校验及远程图片不自动加载的规则。修改解析器或增加插件时，应同步检查生成的 HTML，并维护 `tests/markdown.test.js`。

助手布局及 Markdown 排版统一放在 `styles.css`。大屏面板宽度为 420–560px，桌面高度随窗口调整，小屏保持单列；表格和代码块在自身区域滚动，避免撑破聊天面板。组件只负责显示，不混入工具调用、身份校验或预约确认逻辑。

## 四、统一入口

| 用途 | 当前入口 |
|---|---|
| 完整容器部署 | 根目录 `docker-compose.yml` |
| Windows 本地启动/停止 | 根目录 `start.ps1` |
| API | `uvicorn citymate.app:app` |
| Worker | `python -m citymate.worker` |
| 前端 | `npm run dev`，默认 15173 端口 |
| 后端测试 | `backend` 目录执行 `python -m pytest` |
| 前端测试 | `frontend` 目录执行 `npm test` |
| Python 格式检查 | `python -m black --check citymate tests migrations evals` |
| 前端格式检查 | `npm run format:check` |

Docker Compose 和手动运行使用同一套源码、Dockerfile 与依赖，不再提供并行旧版部署配置。`compose.cached-infra.yml` 只是本机已有镜像的覆盖配置。

## 七、提交前验证

真实服务专用并发与故障用例位于 `backend/tests/test_real_reliability.py`。必须使用 `citymate_test` 与独立 Redis 测试前缀，且不能并行运行共享该库的多个测试任务；缺少真实服务配置时该模块跳过。2026-10-20 已验证原有 31 项及新增 10 项全部通过，步骤与边界见 [并发与故障验证报告](并发与故障验证报告.md)。

在项目虚拟环境中运行后端回归测试、Black 检查，在前端运行测试、格式检查和构建。重点确认登录、管理员权限、订单幂等、预约容量、Feed 分页及模型工具身份约束。

测试数据库必须与业务库隔离。当前默认测试使用 SQLite 与 fakeredis；真实数据库、完整容器构建和外部模型/MCP 联调需要各自的验证环境，不能以格式检查代替。

代码结构整理阶段验收：31 项后端测试通过，4 项 HTTP 客户端测试通过；35 个 Python 文件通过 Black 检查，前端通过 Prettier 检查与生产构建；Compose 配置、PowerShell 启动脚本语法及文档链接检查通过。该阶段没有重新部署容器、连接外部模型或运行完整浏览器业务验收。

随后助手展示优化验收：前端 7 项测试通过（4 项 HTTP、3 项 Markdown），Prettier 检查与生产构建通过，浏览器验证实际模型回复中的标题、表格和加粗。完整分阶段记录见 [开发与验收指南](CITYMATE.md)；本次文档同步未重新运行业务测试。
