# CoursePilot 后端完整使用指南

本指南用于启动 Python 后端、演练课程与教务接口以及核对业务状态。以下命令在 CoursePilot 目录执行。

## 环境与配置

推荐 Python 3.12，依赖见 `requirements.txt`。模型调用需要 `OPENAI_API_KEY`，可通过 `OPENAI_BASE_URL` 接入兼容服务，并设置 `OPENAI_MODEL`。MCP 默认使用官方 SDK 1.9.4，Python 3.9 环境不适用。

从 `.env.example` 复制 `.env` 后配置模型与存储。不要提交密钥。容器与本地开发的主机名和目录不同：

| 配置 | 本地开发示例 | Docker 运行 |
|---|---|---|
| `REDIS_URL` | `redis://:你的密码@127.0.0.1:6379/0` | Compose 自动注入容器主机与密码 |
| `CHROMA_HOST` | `127.0.0.1` | 按容器配置使用 `chromadb` |
| `CHROMA_PORT` | Compose 宿主机映射为 8001 | Chroma 容器端口为 8000 |
| `CHROMA_PERSIST_DIRECTORY` | 本地可写目录 | `/app/data/chroma` |
| `COURSEPILOT_EDUCATION_DB` | 默认 `data/education.sqlite3` | `/app/data/business/education.sqlite3` |
| `COURSEPILOT_KNOWLEDGE_TRANSPORT` | 默认 `mcp`，可显式 `local` | 默认 `mcp` |

## 启动

```powershell
Copy-Item .env.example .env
python -m pip install -r requirements.txt
python -m uvicorn api.main:app --host 127.0.0.1 --port 8000
```

本地方式需先提供可用 Redis，并提供 Chroma 服务或可写本地 Chroma 目录与 embedding 模型缓存。API 自动启动 MCP 子进程，不用手工另开知识服务窗口。

```powershell
docker compose up -d --build
docker compose ps
docker compose logs -f coursepilot
```

容器方式按 `docker-compose.yml` 启动 API、Redis、ChromaDB、Prometheus、Nginx。API 为 `http://localhost:8000`，Swagger 为 `/docs`，Nginx 为 `http://localhost`。Docker 卷默认兼容旧 EchoMind 前缀；已有数据时按配置设置 `COURSEPILOT_VOLUME_PREFIX`，不要为改名删除数据卷。

## 在 PowerShell 中保持同一个会话

```powershell
$apiUrl = 'http://127.0.0.1:8000'
$sessionId = [guid]::NewGuid().ToString()
function Send-CoursePilotMessage([string]$messageText) {
    $body = @{message=$messageText; user_id='student_demo'; conv_id=$sessionId} | ConvertTo-Json
    Invoke-RestMethod -Method Post -Uri "$apiUrl/chat" -ContentType 'application/json; charset=utf-8' -Body ([System.Text.Encoding]::UTF8.GetBytes($body))
}
Send-CoursePilotMessage '转班有什么规定？'
Send-CoursePilotMessage '帮我转到周日班，不想补钱，老师最好不变'
Send-CoursePilotMessage '帮我转到 PY-SUN-PM'
```

最后一步返回草稿，把响应中的真实确认口令作为下一条消息发送。随后询问“我上次申请怎么样了”。状态应为待审核，不是完成转班。不要使用示例字符串代替真实草稿 ID。

## 业务演练

## 10 多轮要求与候选推荐

**源码位置：** `core/transfer_requirements.py` 的 `extract_updates()`、`apply_updates()`、`violations()`；`EducationStore.requirements()`、`update_requirements()`；`agents/transfer_advisor.py` 的 `advise()`、`render_advice()`。

### 10.1 支持的要求

`days`、`excluded_days` 保存允许与排除的日期；`periods`、`excluded_periods` 保存时段；`max_fee_cents` 保存补费上限；`same_teacher` 区分 `required` 与 `preferred`；`target_id` 保存指定班级。

`extract_updates()` 从用户原始消息识别明确支持的表达，并保留 evidence 文本。例如“老师必须不变”是硬性条件，“老师最好不变”是偏好。当前日期、时段和费用主要作为约束处理，并非所有字段都支持任意软偏好。

“改成晚上”覆盖旧时段，但不会删除未被用户修改的预算；“时间不限”清除日期与时段限制；“取消费用限制”清除预算条件。正负条件冲突时返回歧义，`apply_updates()` 不会部分更新并悄悄放宽原条件。

`update_requirements()` 比较更新前后状态，有变化才递增 revision，保存最近修改事件，并把待确认草稿置为过时。要求在会话入口由用户消息更新，不由模型工具参数直接改写。

### 10.2 筛选与排序

`advise()` 查询当前报名和同课程候选，逐个执行政策核验及 `violations()`。全部硬性要求满足后，先按同老师偏好得分排序，再按差价升序，最后用班级 ID 保持稳定顺序。

没有结果时，代码只提出确实能产生可行方案的单条件放宽建议，等待用户同意，不自动执行放宽。多个候选在日期或时段上不同，则计算这些维度的熵，优先询问区分度更高的维度。该追问机制是确定性候选分析，不是模型学习得到的策略。

### 10.3 贯穿示例

默认原班为 `PY-SAT-AM`，周六上午，张老师，已付 2000 元。用户要求周日且零补费时：周日上午班无名额；周日下午班同课程同进度、有名额且零补费；周日晚班需补 200 元。

若追加“老师最好不变”，下午班仍可作为候选，但不满足老师偏好；若改成“老师必须不变”，下午班被排除，晚班又违反零补费要求，系统应解释冲突。若用户明确接受最多补 200 元，则晚班可能满足新的要求。这里的“可能”还需通过当前数据和适用政策核验。

## 12 草稿与确认提交

**源码位置：** `EducationStore.prepare()`、`submit()`、`cancel()`、`invalidate_draft()`；编排器 `_business_control()`。

### 12.1 生成草稿

用户明确选择目标班级后，教务 Agent 可以调用 `prepare_transfer`。`prepare()` 重新查询报名、目标和费用，核验政策及当前要求，无歧义且满足条件才生成草稿。旧待确认草稿变为 superseded，新草稿变为 awaiting_confirmation，同时保存需求 revision 和政策 fingerprint。

准备草稿不创建待审核申请。模型获得的是草稿工具，没有提交工具。

### 12.2 确认提交

`_business_control()` 只接受完整匹配的 `确认提交 <12位小写十六进制草稿ID>`。用户只说“可以”“确认”“好的”时，会显示草稿或提示，不能直接提交。

`submit()` 在事务中依次检查草稿是否属于当前用户与会话、是否已有申请、是否仍待确认，再重新核验源班、目标、费用、需求版本和政策指纹。任何关键变化都使旧草稿失效，要求重新生成并确认。

```text
awaiting_confirmation
  ├─ 用户取消 → cancelled
  ├─ 新草稿或要求变更 → superseded
  ├─ 提交时发现数据变化 → invalidated
  └─ 明确确认且复核通过 → submitted → application.pending_review
```

### 12.3 幂等与事务分别解决什么

幂等防止重复确认创建重复申请：`applications.draft_id` 有唯一约束，提交前先查已存在申请并返回它。事务让同一次提交的校验与状态更新保持一致。

事务不会保证未来审批时仍有名额。本演示不扣减名额、不改变报名，后续真实审批还需要重新校验并完成资源分配。因此不能把这里称为完整名额锁定或支付事务系统。

## 知识导入与检索

`POST /search` 的 `query` 和 `top_k` 是查询参数，不是 JSON body。`POST /knowledge/add` 接收 `documents` 数组，每项包含 title 和 content。以下资料只用于咨询检索，不会自动进入结构化核验索引。

```powershell
Invoke-RestMethod -Method Post -Uri "$apiUrl/search?query=%E8%BD%AC%E7%8F%AD&top_k=3"
$knowledgeBody = @{documents=@(@{title='教务联系说明'; content='演示资料：办理转班请先选择目标班级，再确认草稿。'})} | ConvertTo-Json -Depth 5
Invoke-RestMethod -Method Post -Uri "$apiUrl/knowledge/add" -ContentType 'application/json; charset=utf-8' -Body ([System.Text.Encoding]::UTF8.GetBytes($knowledgeBody))
```

上传文档建议使用 UTF-8 TXT、Markdown 或 JSON 文档数组，限制为 10 MiB。当前上传分支对 `.json` 进行数组解析，其他文件按文本处理；不能据此声称支持 PDF 或 Word 结构解析。导入后检索缓存会清空。管理接口仍没有生产权限控制。

## Skills 与工具轨迹

```powershell
Invoke-RestMethod "$apiUrl/skills"
Invoke-RestMethod -Method Post "$apiUrl/skills/reload"
Invoke-RestMethod "$apiUrl/monitor"
Invoke-RestMethod "$apiUrl/trace/tools?limit=10"
```

记录 `/chat` 返回的 request_id 后，可查询 `/trace/tool/<request_id>`。轨迹保存在进程内有界队列，重启后不保留。

## 常见问题

- 启动失败：先检查模型配置、Redis、MCP 工具发现及 Chroma 数据目录；MCP 失败不静默切本地模式。
- 没有报名：确认演示 user_id 为 `student_demo`；其他 ID 不自动获得这份报名。
- 没有班级候选：检查时间、费用、老师、进度与名额冲突。
- 旧口令无法提交：重新生成并确认草稿，不绕过状态和版本校验。
- 进程退出告警：核对后台任务清理和依赖日志；现有报告记录过 PostHog 兼容告警。

当前为 Python 教务演示后端。`user_id` 由客户端传入，只有 `student_demo` 有预置报名；没有真实登录、审批、支付或退款连接。提交结果为 `pending_review`，不修改报名、不占名额、不扣款。旧客服、作业辅导角色和 Java 描述不属于当前默认业务实现。
