# CoursePilot 有证据的简历指标模板

简历优先使用能对应到报告的结果。能力数量、配置值和质量指标应分别描述。

## 推荐版本

**CoursePilot｜多 Agent 课程咨询与教务办理平台**

**技术栈：** Python、FastAPI、LLM Function Calling、MCP、Redis、ChromaDB、SQLite

**项目介绍：** 面向培训机构学员，构建覆盖课程咨询、选班规划、费用核验与转班申请的对话式演示平台，实现从自然语言需求到待审核申请的业务闭环。

- **Agent 编排与工具调用：** 实现课程咨询、选课规划、教务办理、费用与权益四类 Agent，结合意图识别与任务状态进行路由，采用辅助角色先执行、主角色统一推进的协作流程；支持多轮 Function Calling、角色工具白名单、参数校验与调用轨迹记录。
- **多轮需求与政策核验：** 持久化维护选班条件、硬性要求与偏好，支持多轮条件更新、候选筛选和冲突解释；基于结构化政策索引确定适用条款，按字段白名单查询报名与班级事实，返回逐条判断、条款引用及证据来源。
- **RAG、Skills 与记忆管理：** 通过官方 MCP SDK 的 stdio 协议接入知识检索服务，实现查询改写、多查询并行召回与 LLM 重排，并配置 TTL 缓存、超时、熔断及降级；按角色与关键词动态注入 Skills，使用 Redis 保存近期对话、ChromaDB 保存历史摘要与用户画像。
- **业务可靠性与评测：** 分离草稿生成与确认提交，通过事务、幂等处理、需求版本及政策指纹校验保障提交一致性；实现意图准确率、Macro-F1 与 LLM-as-Judge 评测，开展真实模型全链路回归，结合工具轨迹与数据库状态核验，30 个人工业务场景中 29 个通过预设程序检查。

## 性能与用量口径

同一 full 30 场景报告记录 109 次聊天请求、13 次远端向量请求、服务端返回 182949 tokens，每轮耗时 P50 为 1.532 秒、P95 为 21.500 秒。

这些数字混合确定性业务分支、不同长度对话及后台画像调用口径，不是纯模型延迟，不是并发压测吞吐量，也不能直接转换成价格。只有在面试需要解释观测能力时再展开，不必全部塞入简历。

## 可以引用的实现参数

| 项目 | 当前参数 | 源码 |
|---|---|---|
| 默认角色 | 四类教务 Agent 与人工出口，每类默认一实例 | `agents/agent_orchestrator.py` |
| 模型工具循环 | 最多八轮 | `BaseAgent._call_llm()` |
| 知识工具缓存 | 注册为 300 秒 TTL，进程内缓存 | `api/main.py`、`integrations/tool_manager.py` |
| MCP 读取超时 | 默认 20 秒 | `integrations/knowledge_client.py` |
| 知识工具执行超时 | 默认 30 秒 | `integrations/tool_manager.py` |
| 工作记忆 | 24 小时 TTL，压缩阈值常量 15，保留近期 5 条 | `memory/conversation_memory.py` |

这些是配置和实现范围，不是效果提升。

## 不继续使用的历史数字

91.3% 意图准确率、0.89 Macro-F1、88.7% RAG 准确率、91.2% 召回率、500 条意图标注集及未经验证的提升百分比均不作为当前简历结果。不要把单独修复复测写成整轮 30/30，也不要将 Skills 五场景对照写成稳定提升 20%。

## 后续测量方法

意图准确率和 Macro-F1 需要固定标注集并保存分类结果；检索指标需要查询与相关文档标注；并发性能需要明确部署配置、负载、样本与失败率；Skills 对照需要控制模型和案例并重复运行。新增测量完成后更新报告，再更新简历。

已有评测总结见[联调结果](../data/eval/live-evaluation-summary.md)。
