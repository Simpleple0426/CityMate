## 推荐简历版本

**CoursePilot｜多 Agent 课程咨询与教务办理平台**

**技术栈：** Python、FastAPI、LLM Function Calling、MCP、Redis、ChromaDB、SQLite

**项目介绍：** 面向培训机构学员，构建覆盖课程咨询、选班规划、费用核验与转班申请的对话式演示平台，实现从自然语言需求到待审核申请的业务闭环。

- **Agent 编排与工具调用：** 实现课程咨询、选课规划、教务办理、费用与权益四类 Agent，结合意图识别与任务状态进行路由，采用辅助角色先执行、主角色统一推进的协作流程；支持多轮 Function Calling、角色工具白名单、参数校验与调用轨迹记录。
- **多轮需求与政策核验：** 持久化维护选班条件、硬性要求与偏好，支持多轮条件更新、候选筛选和冲突解释；基于结构化政策索引确定适用条款，按字段白名单查询报名与班级事实，返回逐条判断、条款引用及证据来源。
- **RAG、Skills 与记忆管理：** 通过官方 MCP SDK 的 stdio 协议接入知识检索服务，实现查询改写、多查询并行召回与 LLM 重排，并配置 TTL 缓存、超时、熔断及降级；按角色与关键词动态注入 Skills，使用 Redis 保存近期对话、ChromaDB 保存历史摘要与用户画像。
- **业务可靠性与评测：** 分离草稿生成与确认提交，通过事务、幂等处理、需求版本及政策指纹校验保障提交一致性；实现意图准确率、Macro-F1 与 LLM-as-Judge 评测，开展真实模型全链路回归，结合工具轨迹与数据库状态核验，30 个人工业务场景中 29 个通过预设程序检查。

## 面试介绍与追问

## 20 面试讲解参考

### 20.1 一分钟介绍

CoursePilot 面向培训机构的课程咨询和教务办理。我把业务分为课程咨询、选课规划、教务办理和费用与权益四个角色，通过意图和当前任务状态选择主角色及辅助角色。模型通过白名单工具读取业务数据和知识库；转班要求、草稿和申请存入 SQLite。个人资格由结构化政策条款和报名事实联合核验，提交由完整确认口令触发，并重新检查需求版本、政策和费用。知识检索通过 MCP 接入，另有分层记忆、动态 Skills、工具轨迹与回归评测。当前完成的是演示申请闭环，真实模型一次 30 场景回归中 29 个通过程序检查。

### 20.2 常见追问与回答要点

**为什么要多 Agent？** 业务职责和工具权限不同，费用核验与教务办理可以分别提供信息，再由负责人推进。代价是额外调用和协作耗时；简单问题只用一个角色。没有做充分对照时，不声称多 Agent 必然优于单 Agent。

**为什么不用历史对话直接维护要求？** 历史可能压缩、缺失或被模型误读。任务要求需要结构化、带版本、可在提交时确定性验证。

**如何防止幻觉办理？** 用工具查事实，模型只能准备草稿，确认提交由业务处理器执行；准备和提交都复核，草稿展示由数据库状态生成。自然语言解释仍可能不准确，需要评测和人工检查。

**RAG 与政策规则为什么共存？** RAG 适合获取文本依据，确定性规则适合判断个人是否满足条件。知识相关性不能代替字段比较和事实完整性。

**MCP 在哪里？** 知识客户端通过官方 SDK 启动 stdio 服务、初始化、发现工具和 call_tool；业务数据库工具仍在本地执行。

**29/30 说明什么？** 一次真实模型全链路人工场景回归的程序检查通过情况，覆盖预设状态与工具行为；不能当作线上准确率、Judge 得分或统计显著性结论。

**下一步生产化做什么？** 补充真实鉴权和管理接口权限，将轨迹持久化，处理同会话并发与多进程状态，接入审批系统，完善名额与支付事务，扩充真实用户评测。回答时把这些作为后续工作，不写成已实现。
