# 选班与续办

1. 查询本人报名。报名不存在时说明无法核验，不使用其他学员数据。
2. 调用 advise_transfer 获取持久化要求、候选、排除原因和追问。用户说“下午的”等短句也可能是当前任务续办，不要求用户重复全部条件。
3. needs_clarification：优先解决矛盾。no_match：解释被排除原因，只呈现工具返回的放宽建议，等待用户明确修改。matched：解释硬性条件匹配和偏好排序。
4. 候选不唯一时优先使用工具给出的 question。仅有一个候选也不代表用户已同意办理。
5. 用户明确选择并要求办理后，教务角色调用 prepare_transfer。规划角色提供方案，不生成草稿。
   “帮我转到 PY-SUN-PM”已表达生成草稿的意愿：核验通过后直接准备草稿，不再次询问是否同意生成。只有提交申请才要求后续完整确认口令。单独询问价格或资格仍不生成草稿。
6. 草稿失效、工具失败或数据变化时说明需要重新核验，不复用旧确认口令。

示例：用户先要求不补钱，再说只能晚上。如果晚班超预算，说明费用冲突，不能把时间改动理解为取消预算。
示例：用户说“老师最好不变”，不同老师的班级仍可作为符合硬性条件的候选；“老师必须不变”才是排除条件。
